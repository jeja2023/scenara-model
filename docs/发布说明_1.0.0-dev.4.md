# Scenara Model 1.0.0-dev.4 更新说明

发布日期：2026-09-04

## 变更摘要

- **真实 FastReID 接入准备**：增加 `fastreid` 生产适配器、固定 Linux GPU 环境、FastReID manifest 物化、训练、固定集 CMC/mAP 评估和 ONNX 导出桥接。生产运行强制验证框架提交、环境锁摘要、新鲜 checkpoint、`mAP`、Rank-1、Rank-5、Rank-10、测试集协议和许可证溯源。
- **Windows 功能冒烟**：新增 Windows GPU 冒烟路径，已在 RTX 3070 Laptop GPU 上验证 PyTorch CUDA、FastReID 模型构建与 `[1, 512]` embedding 前向。该路径仅用于开发验证，不替代 Ubuntu 生产运行时。
- **Core 部署反馈闭环**：新增已签名 `deployment-feedback` Webhook 消费端，完全校验 Core HMAC、时间窗和事件信封，按 event ID 幂等写入，防止乱序事件回滚当前状态，并落库审计。
- **PostgreSQL / S3 资格工具**：增加目标环境读写探针、custom-format PostgreSQL 备份、带摘要验证的恢复工具。隔离 PostgreSQL 18.4 与 MinIO 的写读、备份恢复演练已经通过。

## 升级步骤

1. 安装新包并应用元数据迁移：

   ```powershell
   python -m pip install -e ".[dev,postgres,s3]" -c constraints.txt
   scenara-model storage migrate
   ```

2. 若接收 Core 部署反馈，配置共享密钥并在 Core 建立 `model.deployment.changed` 的 Webhook 订阅：

   ```powershell
   $env:SCENARA_MODEL_DEPLOYMENT_FEEDBACK_SECRET="<强随机共享密钥>"
   ```

3. 真实 ReID 训练请在 Ubuntu/Linux GPU 环境构建 `deploy/training/Dockerfile.fastreid`，按 [FastReID训练运行手册](FastReID训练运行手册.md) 先做 runtime preflight；不要使用 Windows 冒烟环境发布模型。

4. 对 PostgreSQL 和 MinIO/S3 目标环境执行 `scripts/qualify_target_environment.py`，对恢复目标完成 `scripts/backup_postgres.py` 与 `scripts/restore_postgres.py` 的演练。只将恢复脚本指向明确批准的空恢复库。
