# 部署反馈消费说明

模型平台通过 `POST /api/v1/deployment-feedback` 消费 Core 发布的 `deployment-feedback` `1.2.0` 事件。该端点为签名 Webhook，不使用迁移期本地登录令牌。

Core Webhook 订阅需要配置以下同一份密钥：

```text
SCENARA_MODEL_DEPLOYMENT_FEEDBACK_SECRET=<强随机共享密钥>
```

请求必须使用 Core 标准事件信封，`event_type` 为 `model.deployment.changed`，`data` 为 `ModelDeploymentEvent`。签名算法与 Core 的 `sign_webhook` 一致：`HMAC-SHA256(secret, "<timestamp>." + raw_body)`，请求头如下：

```text
Scenara-Event-Id: <event_id>
Scenara-Timestamp: <Unix 秒时间戳>
Scenara-Signature: v1=<hex HMAC>
```

默认只接受 300 秒内的请求，可通过 `SCENARA_MODEL_DEPLOYMENT_FEEDBACK_MAX_AGE_SECONDS` 调整。未配置密钥、签名错误、事件头不匹配或超出时间窗时请求会被拒绝，且不会读取 JSON 载荷。

事件以 `event_id` 幂等持久化。相同 ID 与相同正文返回成功但不会重复应用；相同 ID 对应不同正文返回冲突。平台按 `(tenant_id, project_id, capability)` 保存最新的 Core 状态：延迟到达的旧事件仅审计为 `stale`，不会覆盖新状态；声明的 `from_status` 与当前状态不一致的更新会记录为 `rejected_transition`，同样不会改变状态快照。

可使用登录后的 `GET /api/v1/deployment-feedback` 查看消费记录与审计状态。真实订阅仍需由 Core 侧创建，并在隔离环境完成端到端投递验证。
